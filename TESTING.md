# Тесты

Набор тестов для веб-эмулятора x86-ассемблера: 237 проверок, разделённые на
**unit** (проверяют отдельные функции) и **интеграционные** (прогоняют настоящие
программы через парсер и эмулятор, вплоть до интерфейса страницы).

## Быстрый старт

```bash
npm install          # один раз
npm test             # прогнать все тесты
npm run test:watch   # режим наблюдения — перезапуск при изменении файлов
```

Отдельный файл или группа:

```bash
npx vitest run tests/unit/addressResolver.test.ts
npx vitest run tests/integration/lab3-tasks.test.ts
npx vitest run -t "3.0"        # только тесты, в названии которых есть "3.0"
```

Ожидаемый результат:

```
Test Files  11 passed (11)
     Tests  237 passed (237)
```

```

  helpers/run.ts                        запуск программы: парсер → эмулятор → чтение результата
  unit/                                 проверка отдельных модулей
```

### Конфигурация

`vitest.config.ts` повторяет алиасы путей из `vite.config.ts` (`src/…`, `shared/…`,
`entities/…` и т.д.), поэтому тесты импортируют модули так же, как основной код.
Окружение — **jsdom**, потому что почти весь проект работает с DOM: `DataSegment` и
`CodeSegment` строят таблицы, `Debugger` создаёт виджеты, `Registers` обновляет ячейки.

### Хелпер `tests/helpers/run.ts`

Главный инструмент интеграционных тестов. Принимает текст программы и номер
задачи, сам достаёт ограничения, компилирует, выполняет и возвращает результат:

```ts
const r = run(`mov word[45h], 'He'
int 21h`, 3, 0);

r.error          // строка, если программа не собралась
r.dbg            // отладчик: регистры, флаги, память
r.instructions   // сколько инструкций получилось

memText(r.dbg, 0x45, 0x52)   // "Hello, World!" — текст из памяти
reg(r.dbg, 'ax')             // значение регистра
```

Внутри — настоящие `parser`, `Emulator` и `Debugger`, никаких заглушек. Есть защита
от зависания: не более 20 000 шагов на программу. Отдельно есть `compile()` — только
собрать программу, без выполнения (нужно для проверки ошибок компиляции).

## Unit-тесты

### `addressResolver.test.ts` — вычисление адреса памяти

Проверяет функцию `resolveAddress(выражение, регистры)`: превращает содержимое
`byte[...]` / `word[...]` в линейный адрес `0..FFh`.

| Группа | Что проверяется |
|---|---|
| Прямые адреса | `45h`, `4Fh`, `10`, `1010b`, границы `0` и `FFh`, лишние пробелы |
| Косвенная адресация | `si`, `bx`, `si+2`, `bx+si`, `bx+si+4`, полурегистры `bh`/`bl`, вычитание `si-1` |
| Границы сегмента | адрес `100h` отвергается; регистр, уводящий за границу (`si=F5h`, `+10h`); пустое выражение; мусор; несуществующий регистр |
| `parseNumber` | `1Ah`, `FFh`, `1010b`, число без суффикса как hex, пустая строка, мусор |

Отдельный тест фиксирует архитектурное решение: `resolveAddress` сама по себе —
низкоуровневая и складывает любые регистры, а недопустимый `dx` в адресе отсекает
уровень выше (`IndexResolve`) — тест прогоняет полный конвейер и ждёт «Ошибка в индексе».

Проверяет `getRestrists(lab, z)` — то, что задаётся ссылкой `?lab=3&z=2`.

| Группа | Что проверяется |
|---|---|

| Л/Р 1 | 1.1 = `mov,shl,int` + `ax,bx`; 1.2 = `cx,dx`; 1.3 = только `ax`; 1.4 добавляет сдвиги; 1.8 разрешает `loop`; 1.9 — условные переходы; **в каждой задаче есть `int`** |
| Л/Р 2 | 2.0 разрешает `call`, `ret`, `%macro`, `int`; любая задача 2.x наследует команды задачи 1.x (проверяется циклом); 2.1 ограничивает регистры как 1.1 |
| Л/Р 3 | `memory: true` только с Л/Р 3; 3.0 запрещает `bx` и `si`; каждая задача содержит текст задания; задачи с циклами разрешают `loop`/`inc`; 3.4+ — условные переходы; любая задача разрешает `call`/`ret`/`%macro` |

| Структура | у каждого набора непустые `cmd` и `rl`; `lab` проставлен; **команды не повторяются** |

### `halfRegisters.test.ts` — полурегистры

| Группа | Что проверяется |
|---|---|

| Чтение | `AH` = старшие два разряда `AX` (`1234` → `12`), `AL` = младшие (`34`), `DH`/`DL` из `DX` |

### `indexResolve.test.ts` — разбор адресного выражения

| Группа | Что проверяется |
|---|---|
| Прямые адреса | `10h` → `0010`, десятичное `16` → `0010`, двоичное → `000a`, ноль |
| Косвенная адресация | одиночный регистр; **порядок «база + индекс»** (`si+bx` → `bx+si`); смещение с суффиксом `h`; база + индекс + смещение; полурегистры как база |
| Отрицательные смещения | `si-2` → `si+fffeh`, `-2` → `fffe`, `-2` и `0-2` дают одно и то же. **Регресс на два исправленных бага:** раньше терялся знак у одиночного числа и у регистра |
| Недопустимые выражения | два базовых регистра, два индексных, три регистра, умножение регистра, деление на ноль, мусор, пустая строка |
| Арифметика | приоритет умножения над сложением, вычитание, целочисленное деление, смешанные системы счисления (`10h+1+10b` → `0013`) |

### `regexp.test.ts` — обработка текста программы

Парсер приводит код к нижнему регистру и убирает пробелы, но **содержимое кавычек
меняться не должно**. Все преобразования идут через `transformOutsideQuotes`.

| Группа | Что проверяется |
|---|---|
| `transformOutsideQuotes` | преобразуется только код вне кавычек; регистр внутри строки сохраняется; несколько строк в одной строке кода; незакрытая кавычка не ломает обработку; пустая строка |
| `delComments` | комментарий после кода удаляется; `;` внутри строки сохраняется (`'a;b'`, `';'`) |
| `delSpace` | пробелы удаляются из кода; **ведущий и хвостовой пробелы внутри строки сохраняются** (`' W '`) |
| `toLowerCase` | команды и регистры приводятся к нижнему регистру; `'Hello, World!'` и `'A'` не меняются |
| `lineIsEmpty` | пустая строка, строка из пробелов и табуляции, строка с кодом |
| Защита от некорректного входа | `extractSegmentName` и `org100hCheck` не падают на `undefined`; распознавание `codesegment.data` и `org100h` |
| Комплексный сценарий | строка из задания 3.0 проходит все три преобразования подряд и остаётся `'He'` |

## Что тесты нашли в коде

Написание тестов выявило четыре реальных дефекта — все исправлены:

1. **`loop` выполнял лишнюю итерацию.** Условие `CX ≠ 0` проверялось *до* декремента,
   поэтому `CX = 6` давало 7 проходов тела цикла. В x86 сначала декремент, потом
   проверка. Ломало все задачи с `loop` в Л/Р 1 и почти все задачи Л/Р 3.
2. **`loop` и `jmp` переходили на метку, а не на тело.** Метка — отдельный элемент в
   потоке инструкций, переход на неё исполнял её ещё раз. Добавлен `labelBodyIndex()`.
3. **Отрицательное смещение теряло знак.** `byte[-2]` давало адрес `0002` вместо
   `FFFE`, а `si-2` превращалось в `si+0002`. Причина — знак первого операнда не
   учитывался при сведении выражения.
4. **`MOV Память, Память` не отклонялся** — требование задания 3.7 не выполнялось,
   хотя в документации было заявлено. Теперь парсер выдаёт понятную ошибку.
5. **Пустая программа роняла приложение.** Нажатие «Собрать» на пустом редакторе
   приводило к `TypeError: Cannot read properties of undefined (reading 'match')`:
   парсер проверял директивы `segment`/`org 100h` по первой строке, а её нет.
   Теперь печатается «Нет кода для компиляции».

Заодно поправлен разбор метки, имя которой совпадает с командой (`sub:`, `add:`):
раньше такая строка разбиралась как команда и падала с «Неопознанный регистр».

## Соглашения

- Тест описывает **поведение**, а не реализацию: проверяются регистры, ячейки памяти
  и сообщения об ошибках, а не внутренние поля.
- Каждая группа `describe` соответствует одной теме или одной задаче методички.
- В названиях тестов — то, что должно произойти: `запись в AH не меняет AL`.
- Если в тесте используется конкретный набор ограничений, рядом указано, почему
  именно он: `// набор 1.8: mov, loop, shl, inc, int`.
- Тесты не зависят от порядка запуска: `tests/setup.ts` очищает DOM перед каждым.
