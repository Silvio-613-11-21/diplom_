# Asm-эмулятор / for laboratory works

Веб-эмулятор ассемблера для выполнения лабораторных работ по дисциплине
«ЭВМ и ПУ» (NASM-подобный синтаксис). Проект образовательный: эмулируется
подмножество команд процессора, достаточное для лабораторных работ 1–5,
внешний вид повторает дух дебаггера из методички (сегмент кода, регистры,
флаги, стек, дамп памяти).

**Всё работает на стороне клиента** — бэкенда нет, фреймворков нет.
Стек: **Vite + TypeScript + DOM API**.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # сборка в dist/
npm test           # смоук-тесты ядра (43 проверки) без браузера
```

## Ограничения по ссылке

Эмулятору можно задать настройки ссылкой — становятся доступны только те
команды, регистры и возможности, что разрешены заданием:

```
http://…/?lab=1&z=3      — лабораторная 1, задача 3
http://…/?lab=2&z=00     — задача 2.00 (z читается как строка)
http://…/?lab=5&z=8      — задача 5.8
http://…/?lab=1          — без номера задачи: только возможности л/р
http://…/                — свободный режим, ограничений нет
```

Правила ограничений:

* **Л/Р 1** — списки команд/регистров взяты из текстов задач
  (`Разрешено использовать только команды: …`). При явном перечне регистров
  полурегистры запрещены. Стандартное завершение (`mov ax, 4C00h` / `int 21h`)
  разрешено всегда.
* **Л/Р 2** — задачи 2.1–2.10 наследуют ограничения задач 1.1–1.10 и получают
  `call`/`ret` и макросы; задачи без явного перечня (2.0, 2.00, 2.11, 2.12) —
  без ограничений (заглушка в коде).
* **Л/Р 3** — задача 3.0 запрещает регистры BX и SI (по условию), остальные —
  без ограничений (заглушка). Включается память `byte[]/word[]`.
* **Л/Р 4, 5** — явных ограничений в заданиях нет — стоят заглушки
  (`shared/restrictions/tasks.ts`), при необходимости списки легко дописать.

Возможности по лабораторным: макросы и подпрограммы (л/р 2+), память (л/р 3+),
переменные `db/dw/dd/equ/align/times` (л/р 4+), функции ввода-вывода
`int 21h` 01h/02h/09h (л/р 5+).

## Поддерживаемый язык

* Регистры: `AX BX CX DX`, половинки `AH AL BH BL CH CL DH DL`,
  `SI DI BP SP`, сегментные `CS DS ES SS`; флаги `OF DF IF SF ZF AF PF CF`.
* Команды: `mov, xchg, push, pop, add, sub, inc, dec, neg, and, or, xor, not,
  shl, shr, cmp, test, jmp, js, jns, jz/je, jnz/jne, ja, jae, jb, jbe, jl,
  jge, jg, jle, loop, call, ret, int`.
* Числа: `1234h`, `1234`, `1010b`, `0x1F`, символы `'H'`, строки `'el'`;
  `mov word[1], 'el'` пишет два байта.
* Память: 256-байтный дамп 16×16 (`byte[45h]` — 5-я строка, 6-я позиция),
  адресация `byte[si+bx+2]`, `word[si-1]`, `byte[a]`; слова — little-endian.
* Переменные: `a db 12h`, `b dw 1234h`, `c dd …`, `MY equ 123`,
  `align 16, db 90h`, `times 16 db '='`; имя переменной — это адрес
  (`mov dx, MYSTR`, `mov dx, MYSTR+1`).
* Макросы: `%macro Имя N … %endmacro`, параметры `%1…%N`, аргумент с запятой —
  в фигурных скобках `{AX, BX}`.
* Прерывание `int 21h`: `AH=4Ch` — завершение, `AH=01h` — чтение клавиши
  (в т.ч. расширенной — двумя вызовами), `AH=02h` — вывод символа из `DL`,
  `AH=09h` — вывод `$`-строки по адресу в `DX`.
* Директивы оформления: `name: segment .code/.data`, `org 100h`, метки,
  комментарии `;` (в т.ч. внутри строк).

## Архитектура (FSD)

```
src/
├── shared/                    # переиспользуемое, без привязки к приложению
│   ├── types/                 # типы-контракты: asm (IR), machine, restrictions
│   ├── lib/                   # dom-хелперы, системы счисления, ASCII
│   ├── config/messages.ts     # все тексты сообщений (ru)
│   └── restrictions/tasks.ts  # таблица ограничений лабораторных (и заглушки)
├── features/                  # ядро — ЧИСТЫЙ TypeScript, ноль DOM
│   ├── assembler/             # парсер: текст → внутреннее представление
│   │   └── model/             # строки, литералы, макросы, символы, операнды
│   └── emulator/              # виртуальная машина: снимки состояния, шаги
├── entities/                  # сущности отладчика (рисуют состояние)
│   ├── registers/  flags/  code-listing/  memory-dump/  stack-view/
├── widgets/                   # составные блоки интерфейса
│   ├── header/  editor/  control-panel/  debugger/  restrict-info/
├── pages/work/                # рабочая страница
└── app/                       # инициализация, роутер, разбор ?lab=…&z=…
```

Ключевое разделение (главное отличие от предыдущей версии проекта):

* **`features/` не знают про DOM.** Парсер принимает строку и ограничения,
  машина — программу; наружу отдаются снимки состояния (`MachineSnapshot`)
  и результаты шагов (`StepResult`). Ядро можно выполнять в Node — так
  устроены смоук-тесты (`scripts/smoke-test.cjs`).
* **Интерфейс не выполняет команды.** `widgets/control-panel` — единственный
  связующий слой: компиляция → запуск (целиком / по шагам / анимация) →
  отрисовка снимков сущностями. Элементы интерфейса только читают состояние.
* Ограничения проверяются на этапе компиляции: студент сразу видит,
  какая команда или регистр не разрешены заданием, с номером строки.

## Отличия от предыдущей версии

* логика эмулятора и UI полностью разделены (ранее `Emulator` дёргал DOM);
* настоя́щий стек для `call/ret` и `push/pop` (ранее — один адрес возврата);
* корректные флаги (`OF/AF/PF`, `inc/dec` не трогают `CF`), знаковые и
  беззнаковые переходы (`ja/jb` и `jl/jg` теперь различаются);
* полурегистры, переменные, `equ/align/times`, little-endian слова;
* `int 21h` с функциями ввода-вывода и «чёрным экраном»;
* сообщения об ошибках с номерами строк; номера строк в редакторе;
* тёмная тема, выбор системы счисления (HEX/DEC/BIN), легенда переменных;
* z в ссылке читается как строка (`z=0` → 2.0, `z=00` → 2.00).
