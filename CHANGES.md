# Доработка: Л/Р 2 и Л/Р 3

Документ описывает, что было сделано в рамках доработки веб-эмулятора ассемблера
для выполнения лабораторных работ № 2 и № 3.

## Ограничения

* UI (разметка, стили, расположение блоков) **не менялся**.
* Логика существующего кода продолжена: новые возможности встроены в те же классы и
  функции (`parser`, `Emulator`, `Commands`, `DataSegment`, `Registers`, `getRestricts`).
* Кардинальных изменений нет — добавлены новые ветки в существующие `switch`,
  новые поля в типы и новые методы-помощники.

---

## 1. Л/Р 2 — подпрограммы, макросы, библиотеки

### Что уже было и работает

* `%macro NAME N ... %endmacro` — разворачивание макросов с подстановкой `%1..%N`.
* `call` / `ret` — вызов и возврат из подпрограммы.

### Что доработано

1. **Стек адресов возврата вместо одной переменной.**
   Раньше `lastCallIndx` хранил только один адрес, поэтому подпрограмма не могла
   вызвать другую подпрограмму (возврат уходил не туда). Теперь `Emulator.callStack` —
   массив: `call` кладёт адрес, `ret` достаёт последний. Это требование Л/Р 3, где
   задачи вызывают друг друга через макрос и `call`.
   Стек автоматически очищается при старте программы с нулевой строки.

2. **Макрос с нулём параметров** (`%macro name 0`). Раньше `macroCall` возвращал
   `['']` (массив из одной пустой строки), из-за чего проверка числа параметров
   падала с «Ошибка в числе параметров».

3. **Исправлено ложное срабатывание макроса на собственном объявлении.**
   Строка `%macro printhello 2` начинается с имени уже известного макроса, и
   трансформатор пытался вызвать `printhello` с параметром `2`. Теперь строки
   `%macro` / `%endmacro` вызовами не считаются, а имя макроса обязано быть
   отдельным словом.

4. **Полурегистры `AH/AL/BH/BL/CH/CL/DH/DL`.** В примерах заданий Л/Р 2 и в
   формулировках Л/Р 3 они используются напрямую. Регистры хранят 16-битное значение,
   а полурегистр читает/пишет соответствующую половину (`dh` — старший байт `dx`,
   `dl` — младший). Список разрешённых регистров автоматически дополняется
   полурегистрами через `expandRegisters()`.

5. **Условные переходы** `je`, `jne`, `ja`, `jb`, `jl`, `jg`, `jle`, `jge`.
   Они указаны в задании 1.9/1.10 и в наборе команд задания Л/Р 3 — добавлены и в
   парсер, и в эмулятор (по флагам `sf`/`zf`, как в x86).

6. **Вложенные макросы.** Раньше после раскрытия макроса парсер перескакивал
   вставленные строки, поэтому макрос, вызывающий другой макрос, не компилировался.
   Теперь разбор продолжается с той же позиции, и вложенность работает на любую
   глубину.

7. **`int 21h` разрешён во всех наборах ограничений.** Это стандартное завершение
   программы; без него примеры из методички не компилировались на Л/Р 1.2, 1.3 и др.
   Также поправлена задача 1.2 (в наборе не было `mov`, и он не наследовался).

## 2. Л/Р 3 — работа с памятью ЭВМ

### 2.1. Новые операнды: `byte[...]` и `word[...]`

Добавлен разбор обращений к памяти в первом и во втором операнде команды:

```asm
mov byte[5], 'H'      ; один байт (1 символ)
mov word[6], 'el'     ; слово (2 символа)
mov byte[si], 20h     ; косвенная адресация через регистр-указатель
mov byte[si+2], '^'   ; регистр + смещение
mov ax, byte[si]      ; чтение из памяти в регистр
mov cl, word[bx+si]   ; база + индекс
inc byte[si]          ; инкремент ячейки памяти
```

* `mov byte[...], 'A'` — в ячейку пишется код символа.
* `mov word[...], 'el'` — первый символ попадает в младшую ячейку слова (little-endian,
  как в реальной ЭВМ), символы кладутся в память подряд.
* `mov byte[...], byte[...]` — **запрещено** (как в задании 3.7: «MOV Память, Память
  запрещена»), выводится сообщение об ошибке.

### 2.2. Адресные выражения (IndexResolve)

Оптимизирован и расширен разбор адреса `[...]`:

* Поддержаны базовые (`bx`, `bp`) и индексные (`si`, `di`) регистры, а также
  полурегистры `bh/bl/dh/dl` — в задачах Л/Р 3 адрес удобно считать в `BH`/`BL`.
* Допускаются смещения с любой системой счисления (`10`, `10h`, `1010b`) и выражения
  `si+2`, `bx+si+4`, `si-1`.
* Смещение хранится с суффиксом `h`, чтобы при вычислении адреса на этапе выполнения
  его нельзя было спутать с десятичным числом.
* Недопустимые регистры (например, `dx` в адресе) дают ошибку «Ошибка в индексе».

### 2.3. Вычисление адреса при выполнении

Новый модуль `src/features/emulator/model/address/addressResolver.ts` —
`resolveAddress(address, registers)`: подставляет текущие значения регистров и считает
линейный адрес. Поддерживается 16-битная арифметика (отрицательное смещение
превращается в `0FFFFh` и трактуется как «за пределами сегмента»), диапазон адресов —
`0..FFh` (256 байт сегмента данных из `DataSegment.html`).

### 2.4. Модель сегмента данных

`DataSegment` получил методы работы с памятью вместо одного `setValueByCoord`:

| Метод | Назначение |
|---|---|
| `getCellValue(coord)` | чтение одного байта |
| `read(address, 'byte'\|'word')` | чтение байта/слова |
| `write(address, 'byte'\|'word', value)` | запись байта/слова (little-endian) |
| `getChar(address)` | символ в ячейке (для проверки результата) |
| `reset()` | очистка (используется при сбросе) |

Таблица памяти по-прежнему отображает содержимое — записанные символы видны в UI.

### 2.5. Команды работы с памятью в эмуляторе

* `mov` — все комбинации регистр/число/символ/память в обе стороны.
* `add`, `sub`, `and`, `or`, `xor`, `cmp`, `shl`, `shr` — работают и с первым
  операндом-памятью, и со вторым (`and byte[si], 0Fh`).
* `inc`, `dec` — для памяти и для регистров (в т.ч. полурегистров).

Внутренние помощники `Emulator`: `mov`, `readOperand`, `readTarget`, `writeTarget`,
`incDec`, `jumpToLabel`. Они переиспользуются всеми командами, поэтому логика
чтения/записи операндов не дублируется.

### 2.6. Строковые литералы

Символьные строки в программе (`'Hello, World!'`) теперь не портятся:

* регистр букв внутри кавычек **не** приводится к нижнему;
* пробелы внутри строки **не** удаляются;
* комментарии `;` внутри кавычек не обрезаются.

Для этого в `RegExp` (parser) добавлен `transformOutsideQuotes`, а `toLowerCase`,
`delSpace`, `delComments` применяют преобразование только к коду вне кавычек.

### 2.7. Отображение в CodeSegment

* Команды с памятью показываются как в исходнике: `mov word[45h], 'He'`,
  `inc byte[si]`.
* Адрес в отладчике показывается в том виде, в каком его написал пользователь.

## 3. Ограничения по ссылке (задачи Л/Р 3)

`Restricts` расширен тремя необязательными полями:

```ts
export interface Restricts {
    lab?: number;
    cmd: string[];
    rl: string[];
    memory?: boolean;          // разрешена ли работа с byte[]/word[]
    indexRegs?: string[];      // какие регистры допустимы в адресе памяти
    forbiddenRegs?: string[];  // какие регистры запрещены условием задачи
    task?: string;             // текст задания для блока ограничений
}
```

### 3.1. Наборы задач

Все задачи Л/Р 3 (3.0, 3.00, 3.1 … 3.8) заданы в `getRestricts.ts`:

| `z` | Задача | Особенность набора |
|---|---|---|
| 0 | 3.0 «Hello, World!» | `forbiddenRegs: ['bx','si']` — по условию |
| 1 | 3.00 через `SI` | базовый набор |
| 2 | 3.1 надпись с ФИО | + `mov` |
| 3 | 3.2 заполнение `'^'` | + `loop`, `inc` |
| 4 | 3.3 область между DH и DL | + `loop`, `inc`, `cmp`, переходы |
| 5 | 3.4 длина по скобку | + циклы, переходы |
| 6 | 3.5 затирание между скобками | + `dec` |
| 7 | 3.6 затирание до/после | + `dec` |
| 8 | 3.7 копирование фрагмента | + `dec` |
| 9 | 3.8 подсчёт символа | + арифметика и сдвиги |
| -1 | все задачи | полный набор |

Каждый набор уже включает `call`, `ret`, `%macro` и `int` — по методичке все задачи
Л/Р 3 оформляются подпрограммами и вызываются через универсальный макрос из Л/Р 2.

### 3.2. Проверки в парсере

* `memory` — если работа с `byte[]`/`word[]` не разрешена, парсер возвращает
  «Работа с памятью в этой работе запрещена» (Л/Р 1 и Л/Р 2).
* `forbiddenRegs` — проверка по **исходному тексту** (до удаления пробелов), чтобы
  не было ложных срабатываний и пропусков. Учитываются полурегистры: если запрещён
  `bx`, то запрещены и `bh`, `bl`.
* `indexRegs` — какие регистры можно использовать в адресном выражении.

### 3.3. Блок ограничений

`RestrictInfo` теперь выводит для Л/Р 3:

1. список разрешённых команд,
2. список регистров и упоминание `byte[] / word[]`,
3. **текст конкретного задания** (третья строка блока).

Мелкая ошибка `restricts.lab = 3` (присваивание вместо сравнения), из-за которой
условие всегда было истинным, исправлена на `===`.

## 4. Исправленные ошибки, мешавшие сборке

* `RegisterValue.ts` отсутствовал (импортировался в `commands.ts`) — добавлен тип.
* `RestrictInfo.ts` импортировал `Restrictinfo.html`, а файл называется
  `RestrictInfo.html` — работало только на Windows (регистронезависимая ФС).
* `npm run build` падал на неиспользуемых переменных (`noUnusedLocals`) — код
  почищен, устаревшие/дублирующие ветки убраны.
* `vite.config.ts` — добавлен `server.allowedHosts`, иначе dev-сервер отдаёт 403 при
  открытии через preview-хост.

## 5. Защита от зависаний

* `run-all` ограничен 1 000 000 шагов: при бесконечном цикле пользователь получает
  сообщение, а страница не подвисает.
* `loop` больше не выполняет вычисления с `NaN` при некорректном `CX`.
* Разворачивание макросов ограничено (5000 раскрытий / 10 000 строк): рекурсивный
  макрос даёт сообщение «Слишком глубокая вложенность макросов», а не зависание.
* Запись по адресу за пределами сегмента (`0..FFh`) перехватывается с сообщением
  «Неверный адрес памяти».
