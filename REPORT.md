# Отчёт по доработке веб-эмулятора ассемблера

**Проект:** учебный веб-эмулятор x86-ассемблера (`github.com/Silvio-613-11-21/diplom_`)
**Объём работ:** поддержка лабораторных работ № 2 и № 3
**Дата:** ноябрь 2026

---

## 1. Постановка задачи

Требовалось доработать существующий эмулятор так, чтобы на нём можно было выполнять
задания лабораторных работ:

* **Л/Р 1** — уже реализована ранее (не трогалась, кроме уточнения наборов ограничений);
* **Л/Р 2** — «Подпрограммы, макросы, библиотеки»: не хватало части команд;
* **Л/Р 3** — «Работа с памятью ЭВМ»: требовалось реализовать полностью;
* плюс наборы ограничений для всех задач, задаваемые через параметры URL.

Ограничения постановки:

| Ограничение | Как выполнено |
|---|---|
| Вся работа на клиенте, без бэкенда | Всё в TypeScript в браузере, новых сетевых вызовов нет |
| Не менять UI | Разметка и стили не тронуты; менялись только данные и логика |
| Продолжать логику и стиль существующего кода | Новое встроено в существующие классы/функции (`parser`, `Emulator`, `Commands`, `DataSegment`) |
| Кардинальные изменения только при необходимости | Новые модули: `addressResolver.ts`, `HalfRegisters.ts`, `RegisterValue.ts` |
| Ограничения задач — через URL (`lab`, `z`) | Всё в `getRestricts(lab, z)` |

## 2. Исходное состояние проекта

Проект построен по FSD-подобной структуре:

```
src/
  app/          — точка входа, роутер
  pages/        — Workpage (страница работы)
  widgets/      — ControlPanel, Debugger, RestrictInfo
  entities/     — DataSegment, CodeSegment, Registers
  features/
    parser/     — разбор текста программы
    emulator/   — выполнение инструкций
  shared/       — типы, ограничения, утилиты
```

Поток обработки программы:

```
текст в редакторе
   ↓ parser()          — проверки ограничений, разворот макросов, разбор строк
   ↓ AllInstructions[]
   ↓ Emulator.emulate() — выполнение одной инструкции за шаг
   ↓ Debugger           — регистры, флаги, память, строка кода, консоль
```

Что уже работало до доработки: разбор команд, регистры, флаги, `loop`, `jmp`,
`call`/`ret` (частично), `%macro`, таблица сегмента данных, отладчик по шагам.

Что не работало или отсутствовало: обращения к памяти `byte[]`/`word[]`,
полурегистры, условные переходы, вложенные вызовы, вложенные макросы, наборы
ограничений для Л/Р 3.

## 3. Л/Р 2. Подпрограммы, макросы, библиотеки

### 3.1. Постановка

В работе требовалось:

* объявить именованную подпрограмму (`sd:`, тело, `ret`), в том числе пустую;
* написать универсальный макрос с 5 параметрами `%macro initregs 5`, который
  заполняет `AX`, `BX`, `CX`, `DX` и вызывает подпрограмму, переданную пятым
  параметром;
* переделать все задачи Л/Р 1 в виде макроса + подпрограммы.

### 3.2. Что было исправлено

**в) Стек адресов возврата вместо одной переменной.**

Изначально адрес возврата хранился в одном поле:

```ts
private static lastCallIndx: number | undefined = undefined;
```

Этого достаточно для плоской программы, но как только подпрограмма вызывает другую
подпрограмму, единственное значение затирается и `ret` уходит не туда. Заменено на
стек:

```ts
private static callStack: number[] = [];
```

`call` кладёт адрес в стек, `ret` снимает последний. Стек сбрасывается при старте
программы с нулевой строки, чтобы остатки прошлого запуска не влияли на новый.

**г) Макрос с нулём параметров.**

`macroCall` для строки вида `%macro name 0` возвращал массив `['']` вместо пустого,
из-за чего проверка `macro.paramsCount !== paramsArr.length` давала ошибку
«Ошибка в числе параметров» на корректном макросе. Исправлено.

**д) Ложное срабатывание макроса на собственном объявлении.**

Строка `%macro printhello 2` начинается с уже зарегистрированного имени макроса,
и трансформатор пытался «вызвать» `printhello` с параметром `2`. Теперь строки
`%macro`/`%endmacro` никогда не считаются вызовами, а имя вызова обязано быть
отдельным словом:

```ts
// было: /[a-z0-9_]/  — цифра в имени не давала распознать конец
// стало: /[a-z_]/     — цифры допустимы в аргументах (50h, 10h)
```

**е) Вложенные макросы.**

После раскрытия макроса парсер делал `i += newLines.length`, перескакивая только
что вставленные строки. Если вставленный код сам вызывал макрос, вызов оставался
необработанным и падал на «Неопознанная команда». Теперь после раскрытия разбор
продолжается с той же позиции:

```ts
lines.splice(i, 1, ...newLines);
expansions++;
// остаемся на той же позиции: вставленные строки тоже могут содержать вызовы
continue;
```

**ж) Полурегистры `AH/AL/BH/BL/CH/CL/DH/DL`.**

Задания Л/Р 2 и Л/Р 3 активно используют полурегистры (`DH` — позиция символа,
`DL` — счётчик). Регистры хранят 16-битное значение, полурегистр адресует
соответствующий байт:

```ts
// HalfRegisters.ts
export const HalfRegister = {
    ah: { parent: 'ax', high: true },  al: { parent: 'ax', high: false },
    bh: { parent: 'bx', high: true },  bl: { parent: 'bx', high: false },
    ch: { parent: 'cx', high: true },  cl: { parent: 'cx', high: false },
    dh: { parent: 'dx', high: true },  dl: { parent: 'dx', high: false },
}
```

Чтение `DH` возвращает старший байт `DX`, запись в `DH` меняет только старший байт,
не задевая `DL`. Список разрешённых регистров автоматически дополняется
полурегистрами родительских регистров.

**з) Условные переходы.**

Добавлены `je`, `jne`, `ja`, `jb`, `jl`, `jg`, `jle`, `jge` — по флагам `sf`/`zf`,
как в реальном x86. Без них не выполняются задания 1.9/1.10 и почти все задачи Л/Р 3.

**и) `int 21h` разрешён во всех наборах.**

Это стандартное завершение COM-программы, оно есть и в примерах методички, но
отсутствовало в некоторых наборах (1.2, 1.3, 2.0), из-за чего корректный код не
компилировался. Добавлено везде, включая задачу 2.0.

## 4. Л/Р 3. Работа с памятью ЭВМ

### 4.1. Постановка

По методическим указаниям сегмент данных — 256 байт (`org 100h`, адреса `0..FFh`).
Доступ к памяти — через `byte[]` и `word[]`:

```asm
mov byte[5], 'H'        ; запись одного символа (байт)
mov word[6], 'el'       ; запись двух символов (слово)
mov al, byte[si]        ; чтение байта через указатель SI
mov byte[si+2], '^'     ; указатель + смещение
```

Ключевые правила из методички:

* `word` — 2 байта, младший адрес — первый символ (little-endian);
* только `BX` может складываться с `SI` (`[bx+si]`);
* `MOV Память, Память` запрещено — копирование только через регистр;
* все задачи оформляются подпрограммами и вызываются через макрос из Л/Р 2.

### 4.2. Что было добавлено

**Модель типов операндов.**

```ts
export interface MemoryOperand {
    address: string;   // адресное выражение: "45h", "si", "si+2", "bx+si"
    system: 'byte' | 'word';
}
```

`AllInstructions` расширен: `targetMemory?: MemoryOperand` (первый операнд-память)
и `sourceMemory?: MemoryOperand` (второй операнд-память).

**Разбор `byte[...]` / `word[...]`** в `SimpeInstructionsReader` и
`InstructionsInspector`: система счисления (`byte`/`word`) и содержимое скобок
разделяются; содержимое сохраняется как адресное выражение.

**Адресные выражения** (`IndexResolve`):

| Форма | Пример |
|---|---|
| константа в любой СС | `10h`, `16`, `10000b` |
| база | `[bx]`, `[bp]`, `[bh]`, `[bl]` |
| индекс | `[si]`, `[di]` |
| база + индекс | `[bx+si]`, `[bx+di]` |
| регистр + смещение | `[si+2]`, `[bx-1]` |
| база + индекс + смещение | `[bx+si+4]` |

Смещения нормализуются к шестнадцатеричной форме с суффиксом `h`, чтобы на этапе
выполнения их нельзя было спутать с десятичными числами.

**Вычисление адреса во время выполнения** — новый модуль
`src/features/emulator/model/address/addressResolver.ts`:

```ts
resolveAddress(address: string, registers: Registers): number | undefined
```

Функция подставляет текущие значения регистров, складывает компоненты, проверяет
границы (`0..FFh`). Некорректный адрес даёт `undefined`, и эмулятор печатает
«Неверный адрес памяти (допустимы адреса от 0 до FF)» и останавливает программу.

**Сегмент данных** (`DataSegment`) получил методы доступа:

| Метод | Назначение |
|---|---|
| `getCellValue(coord)` | чтение байта |
| `read(address, system)` | чтение байта или слова |
| `write(address, system, value)` | запись байта или слова |
| `getChar(address)` | символ в ячейке |
| `reset()` | полная очистка |

Запись слова раскладывается по двум соседним ячейкам (младший байт — по меньшему
адресу, как в реальной ЭВМ).

**Команды с памятью** в эмуляторе: `mov`, `add`, `sub`, `and`, `or`, `xor`, `cmp`,
`shl`, `shr`, `inc`, `dec` работают с операндом-памятью в любой позиции.
Внутренние помощники (`readOperand`, `readTarget`, `writeTarget`, `incDec`)
переиспользуются всеми командами, поэтому логика чтения/записи операндов живёт
в одном месте.

**`MOV Память, Память` запрещено** — по требованию задания 3.7 выводится
соответствующая ошибка.

### 4.3. Строковые литералы

Задания Л/Р 3 записывают надписи прямо в память: `mov word[...], 'He'`. Проблема
была в том, что глобальные преобразования текста программы (приведение к нижнему
регистру, удаление пробелов, отрезание комментариев) портили содержимое кавычек:
`'Hello, World!'` превращалось в `'hello,world!'`.

В `RegExp` (модуль парсера) добавлен `transformOutsideQuotes` — преобразование
применяется только к частям строки вне кавычек. Теперь:

* регистр букв внутри кавычек сохраняется;
* пробелы внутри строки сохраняются;
* `;` внутри кавычек не считается началом комментария.

### 4.4. Отображение

`CodeSegment` показывает инструкции с памятью в привычном виде:
`mov word[45h], 'He'`, `inc byte[si]`. Шаг отладчика подсвечивает строку исходной
программы корректно в том числе для строк, полученных раскрытием макроса.

## 5. Ограничения по ссылке

### 5.1. Формат ссылки

```
index.html?lab=3&z=2
```

`lab` — номер работы, `z` — номер задачи. `z=-1` — набор «все задачи работы».

### 5.2. Структура ограничений

```ts
export interface Restricts {
    lab?: number;
    cmd: string[];             // разрешённые команды
    rl: string[];              // разрешённые регистры общего назначения
    memory?: boolean;          // разрешена ли работа с памятью
    indexRegs?: string[];      // допустимые регистры в адресном выражении
    forbiddenRegs?: string[];  // регистры, запрещённые условием задачи
    task?: string;             // текст задания
}
```

### 5.3. Наборы задач Л/Р 3

| `z` | Задача | Специфика набора |
|---|---|---|
| 0 | «Hello, World!» с 5-й строки, по 2 символа | `forbiddenRegs: ['bx', 'si']` |
| 1 | то же с использованием `SI` | базовый набор |
| 2 | надпись с ФИО, макрос вызван дважды | базовый набор |
| 3 | заполнение `'^'` от 0 до `DH` | `loop`, `inc`, `dec`, `cmp`, переходы |
| 4 | заполнение между `DH` и `DL` | те же + `rl` без `bp`/`sp` |
| 5 | длина надписи до закрывающей скобки | те же |
| 6 | затирание между скобками (через задачи 3.4 и 3.3) | те же |
| 7 | затирание до и после надписи | те же |
| 8 | копирование фрагмента (через регистр) | те же |
| 9 | подсчёт вхождений символа | + арифметика и сдвиги |
| −1 | все задачи | полный набор |

Все наборы включают `call`, `ret`, `%macro` — по методичке любая задача Л/Р 3
оформляется подпрограммой, вызываемой через универсальный макрос из Л/Р 2.

### 5.4. Проверки в парсере

* **Память.** Если `memory !== true` (Л/Р 1 и 2), любое обращение к `byte[]`/`word[]`
  даёт «Работа с памятью в этой работе запрещена».
* **Запрещённые регистры.** Проверка выполняется по исходному тексту строки
  (после удаления комментариев, но до удаления пробелов), с учётом границ слов и
  полурегистров: запрет `bx` означает запрет `bh` и `bl`.
* **Индексные регистры.** Регистры в адресном выражении сверяются с `indexRegs`;
  недопустимый даёт «Ошибка в индексе».
* **Команды.** Неизвестная или неразрешённая команда даёт «Неопознанная команда».

### 5.5. Блок ограничений на странице

`RestrictInfo` теперь выводит для Л/Р 3 три части: разрешённые команды, разрешённые
регистры (с упоминанием `byte[] / word[]`) и текст конкретного задания. Заодно
исправлена опечатка `restricts.lab = 3` (присваивание вместо сравнения), из-за
которой условие срабатывало всегда.

## 7. Исправленные ошибки сборки

Проект собирался только на Windows; на Linux/macOS сборка падала. Исправлено:

1. **Отсутствовал `RegisterValue.ts`** — импортировался в `commands.ts`, но файла в
   репозитории не было. Добавлен.
2. **`import './Restrictinfo.html?raw'`** — реальный файл называется
   `RestrictInfo.html`. На Windows регистр не важен, на Linux — важен. Исправлено.
3. **Неиспользуемые переменные** (`noUnusedLocals`) — около 11 ошибок в
   `route.ts`, `CodeSegment.ts`, `addressResolver.ts`, `MacrosReader.ts`, `parser.ts`,
   `Worpkage.ts`, `ControlPanel.ts`. Код почищен.
4. **Нет `vite.config.ts`** — добавлен с алиасами путей (`src`, `shared`, `widgets`,
   `entities`, `features`, `pages`, `app`) и `server.allowedHosts`, без которого
   dev-сервер отдаёт 403 при открытии через внешний хост.

Итог: `npm run build` (tsc + vite) проходит без ошибок и предупреждений,
бандл ~65 КБ (17 КБ gzip).

  полурегистры, переходы, копирование через регистр), но эталонные тексты программ
  сверить не с чем.
* **Библиотеки через `%include`** — методичка упоминает вынесение подпрограмм в
  отдельные файлы, но в веб-версии редактор одностраничный, поэтому поддержано
  объявление всех макросов и подпрограмм в одном тексте.
* **Метки внутри макроса** — по методичке такие метки можно использовать один раз.
  Это ограничение архитектуры x86-макросов, отдельно не обходилось.
